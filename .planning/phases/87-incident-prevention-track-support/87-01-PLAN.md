    **1. Schema default change** (line ~5):
    ```sql
    ALTER TABLE projects
      ALTER COLUMN active_tracks SET DEFAULT '{"adr":false,"biggy":false,"incident_prevention":false}'::jsonb;
    ```

    **2. Additive backfill with guard against re-run overwrite** (per Pitfall 1 in RESEARCH.md):
    ```sql
    UPDATE projects
      SET active_tracks = active_tracks || '{"incident_prevention":false}'::jsonb
      WHERE active_tracks ? 'adr'
        AND NOT (active_tracks ? 'incident_prevention');
    ```
    The `NOT (active_tracks ? 'incident_prevention')` guard is mandatory — without it, re-running this migration would silently overwrite a user's `incident_prevention: true` value (set via Settings) back to false.
