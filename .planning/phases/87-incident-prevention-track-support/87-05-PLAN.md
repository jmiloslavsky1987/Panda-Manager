<objective>
Add retroactive seeding on the Settings track-toggle path. When a user flips `incident_prevention: false → true` in Admin > Project Settings, the PATCH route must (a) detect the flip by comparing the new vs old `active_tracks`, (b) call the shared `seedIncidentPreventionForProject` helper inside the same transaction as the project update, and (c) be safely double-toggle-able. The form UI gets a third checkbox and is hardened to always send a complete 3-key object to avoid the JSONB-merge gotcha (Pitfall 2 in RESEARCH.md).

Purpose: The CONTEXT.md mid-engagement scenario — customer buys Change Risk Prediction six months into an ADR engagement and flips the IP toggle ON — requires this code path. Without it, the user sees an empty IP track with no WBS, no arch nodes, and no onboarding phases.
Output: ~80 LOC added to the settings PATCH route; ~15 LOC of UI changes in ProjectSettingsForm.
</objective>
