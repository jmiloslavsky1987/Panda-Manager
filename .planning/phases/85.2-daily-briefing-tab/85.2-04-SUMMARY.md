## Refactor Diff at High Level

**Before (forEach fire-and-forget):**
```
handleGenerate(): void
  selectedCards.forEach(async (card) => {
    fetch + SSE consumer — no await, no chaining
  });
  // returns immediately, no way to know when all finish
```

**After (Promise.all + chain):**
```
generateSingleCard(card): Promise<void>   // extracted SSE consumer
chainToBriefing(date): Promise<void>      // new — POST briefing route, navigate

handleGenerate(): Promise<void>
  await Promise.all(selectedCards.map(generateSingleCard))
  await chainToBriefing(selectedDate)
```

## chainToBriefing Flow

1. POST `/api/daily-prep/briefing` with `{ date: selectedDate }` body
2. Check `response.ok && response.body` — log + return early on HTTP error (no navigation)
3. Drain SSE stream line-by-line via ReadableStream reader
4. On `event: done` line: `router.push('/daily-prep/briefing')` then return
5. On stream end without `event: done`: silently exit (no navigation)
6. On fetch exception: `console.error(...)` — no navigation

Streaming text is intentionally not rendered on the Calendar tab — the Briefing tab's `page.tsx` (Plan 03) fetches the persisted row via GET on mount.

## Parallel Generation Timing Preserved

The `generateSingleCard` extraction preserves all `setCards(prev => ...)` functional updater calls verbatim. Per-card state transitions (loading → streaming text → done with expanded:true, selected:false) still occur independently as each event's SSE stream resolves — NOT batched at the end of Promise.all. `Promise.all` only gates `chainToBriefing` until all cards are done; it does not change when individual card state updates happen.

## Carry-Forward for Plan 05

Plan 05 is human verification. The end-to-end flow to test:
1. Visit `/daily-prep`, select 1-2 calendar events
2. Click Generate Prep
3. Per-event brief cards stream in concurrently (network tab shows N parallel fetch calls to `/api/daily-prep/generate`)

5. App auto-navigates to `/daily-prep/briefing`
6. Briefing tab renders the synthesized markdown (fetched from DB via GET)

No Docker rebuild required for this plan — pure Client Component changes, no new environment variables, no new dependencies.
