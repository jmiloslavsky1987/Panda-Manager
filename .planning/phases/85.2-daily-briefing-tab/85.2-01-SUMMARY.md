## calendarEvents Discovery

The plan listed `calendarEvents` as a Drizzle schema table. It does NOT exist in `db/schema.ts` or any migration — calendar events come exclusively from the Google Calendar API (via `app/api/time-entries/calendar-import/route.ts` returning `CalendarEventItem[]`).

**Decision:** `fetchTodayMeetingsAndBriefs` returns:
- `meetingsWithBriefs`: from `daily_prep_briefs` table (DB-backed, reliable)
- `meetingsWithoutBriefs`: always `[]` from this helper — the route layer (Plan 02) must cross-reference the Google Calendar API response with the stored briefs to populate this array

This is documented in the function JSDoc comment and is architecturally correct.

## Project Membership Helper

No `getUserProjectIds` or similar helper exists in `lib/`. Per CONTEXT.md, this is a single-user app. All fetchers accept `_userId` parameter (prefixed with `_` to suppress TS unused-variable warning) for Phase 86 SSO readiness, but currently fetch across all projects without ownership filtering.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] UNIQUE INDEX regex test failure**
- **Found during:** Task 1 verification
- **Issue:** Initial migration had `CREATE UNIQUE INDEX IF NOT EXISTS daily_briefings_user_date` on its own line with `ON daily_briefings (user_id, date)` on the next line. The BRIEF-01c test regex `/CREATE UNIQUE INDEX.*user_id.*date/i` requires both on the same line.
- **Fix:** Moved entire `CREATE UNIQUE INDEX IF NOT EXISTS daily_briefings_user_date ON daily_briefings (user_id, date);` onto a single line.
- **Files modified:** `db/migrations/0051_daily_briefings.sql`
- **Commit:** 5a1a3292 (included in same commit after re-test)

**2. [Rule 1 - Bug] TypeScript type errors in lib/daily-briefing.ts**
- **Found during:** Task 2 TypeScript compilation check
- **Issue:** `.map().filter((x): x is T => x !== null)` pattern produces TS errors when map returns `(T | null)[]` — type predicate in filter is considered unsafe; sort lambda also triggered `possibly null` errors.
- **Fix:** Replaced with explicit `for` loop + `push` pattern which TypeScript correctly narrows.
- **Files modified:** `lib/daily-briefing.ts`
- **Commit:** 9f266e31 (included in Task 2 commit)

**3. [Rule 2 - Missing functionality] calendarEvents schema table not found**
- **Found during:** Task 2 implementation
- **Issue:** Plan listed `calendarEvents` as a Drizzle import from `@/db/schema`, but no such table exists. Calendar data comes from Google Calendar API only.
- **Fix:** `fetchTodayMeetingsAndBriefs` returns `dailyPrepBriefs` rows for `meetingsWithBriefs`; `meetingsWithoutBriefs` is always `[]` from this helper. Added JSDoc comment explaining the route layer must enrich this from the API.
- **Impact:** Wave 2 route (Plan 02) must handle the Google Calendar event join itself. This is architecturally correct separation of concerns.
- **Files modified:** `lib/daily-briefing.ts`

## Carry-Forward Decisions for Plans 02 and 03

1. **Route must join calendar API with DB briefs:** Call `GET /api/time-entries/calendar-import?date=YYYY-MM-DD` (or reuse `getCalendarClient()` from that route file) + cross-reference with `fetchTodayMeetingsAndBriefs` result to build the full synthesis input.

2. **Column names to use:** `actions.description`, `risks.description`, `milestones.name`, `keyDecisions.decision` (NOT `title` — the schema has no `.title` on any of these tables).

3. **ActionCandidate.description** (not `.title`) is what gets passed to Claude for synthesis.

4. **dailyBriefings INSERT pattern:** Use `INSERT ... ON CONFLICT (user_id, date) DO UPDATE SET briefing_content = EXCLUDED.briefing_content, generated_at = now()` for regeneration support.

5. **`gte` from drizzle-orm** works for ISO date string comparisons on TEXT columns (lexicographic sort is correct for YYYY-MM-DD format).
