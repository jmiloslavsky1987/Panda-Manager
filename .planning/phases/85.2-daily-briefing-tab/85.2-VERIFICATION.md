## Gaps

### Gap 1 — Briefing markdown contrast/visibility regression

**id:** brief-gap-01-prose-contrast
**status:** resolved
**severity:** blocker (the feature is unreadable to the user)
**surface:** `app/daily-prep/briefing/page.tsx`

**Observed:** Section headings (`## Today's Meetings`, `## Today's Action Items`, `## This Week's Critical Items`) and the leading bold text on each item render near-white on the light page background. Only the body description text is legible. Visible in screenshot taken during manual UAT 2026-05-14. The Calendar tab and the rest of the app render text normally.

**Likely root cause:** `app/daily-prep/briefing/page.tsx:114, 172` renders inside `<div className="prose prose-sm dark:prose-invert">`. `dark:prose-invert` is being applied while the surrounding page background remains light — yielding light-text-on-light. Either the user's environment matches `dark:` but no `dark:bg-*` is set on this route, or `@tailwindcss/typography` is not installed and only a residual stylesheet is overriding heading/strong colors. The streaming-state branch has the same class string, so it would fail identically.

**Acceptance:**
- H2 headings and bold spans inside the rendered briefing have ≥ WCAG AA contrast against the page background in both light and dark modes
- Streaming state (`Synthesizing…`) renders with the same legibility
- No reliance on a `prose-invert` class unless the page background also flips

### Gap 2 — Action Items and Critical Items don't show customer/project

**id:** brief-gap-02-customer-attribution
**status:** resolved
**severity:** high (synthesis lacks the context that makes the briefing actionable)
**surface:** `app/api/daily-prep/briefing/route.ts` (system prompt + user payload), possibly `lib/daily-briefing.ts` (candidate fetchers)

**Observed:** In the rendered briefing, action items read like `"Confirm go-live date with executive sponsors — overdue since May 1..."` with no customer name attached. Critical items have the same problem. The user cannot tell which account/project each line refers to. Today's Meetings does mention "NOC BigPanda Onboarding" (in the title), so meetings aren't affected; the gap is on Action Items and Critical Items.

**Likely root cause (two parts to verify during planning):**
1. `app/api/daily-prep/briefing/route.ts:20-33` SYSTEM_PROMPT does not require customer/project attribution on Action Items or Critical Items.
2. `fetchTodayActionCandidates` / `fetchWeekCriticalCandidates` (`lib/daily-briefing.ts`) may not be joining customer or project name into the candidate rows passed to Claude. If the data isn't there, the prompt fix alone won't help.

**Acceptance:**
- Each Action Item line names the customer (and/or project) it belongs to
- Each Critical Item line names the customer (and/or project) it belongs to
- If an item is global / no customer attached, render `"Internal"` or omit gracefully — do not show `"undefined"` or empty
- New behavior is covered by a RED test before implementation lands
