## Summary

Phase 85.2 adds a synthesis layer on top of the existing per-meeting brief pipeline (Phase 80). The briefing page is a new Next.js App Router sub-route under `/daily-prep/briefing` wired through a new `layout.tsx` that renders `SubTabBar`. The API route follows the exact same SSE streaming + DB persist pattern as `/api/daily-prep/generate`, consuming data from four heuristic queries (actions, risks, milestones, WBS) and the existing `daily_prep_briefs` table. The most significant technical risks are the TEXT date field heuristics (requires JS-side filtering, not SQL comparison) and the `app/daily-prep/page.tsx` chain-to-briefing modification (must not break existing parallel SSE generation pattern).

The project already has all required infrastructure: `SubTabBar` is a 42-line component that accepts `items[]` + `activeSubtab` prop; `DailyPrepCard` uses `ReactMarkdown` + `rehype-sanitize`; the `daily_prep_briefs` table and SSE streaming pattern are fully established; `useRouter` from `next/navigation` is used in multiple client components. No new dependencies are needed.

**Primary recommendation:** Follow the generate route exactly — POST → SSE stream → persist on `event: done`. Add `app/daily-prep/layout.tsx` as a `'use client'` component that reads `usePathname()` and passes the derived `activeSubtab` id to `SubTabBar`. Keep heuristic filtering entirely in TypeScript (fetch candidates, filter with `parseFlexibleDate`), not in SQL.

### Pattern 2: SSE Streaming Route (POST → stream → persist)

**What:** Exact copy of `/api/daily-prep/generate/route.ts` structure. `ReadableStream` with `start(controller)`, text events as `data: { text }`, terminal `event: done\ndata: {}`, DB persist after `finalMessage()`.

**When to use:** Any route that streams Claude output and needs to persist the full result after streaming.

**Example (from generate/route.ts — verified in codebase):**
```typescript
// Source: /Users/jmiloslavsky/Documents/Panda-Manager/app/api/daily-prep/generate/route.ts
const stream = new ReadableStream({
  start(controller) {
    (async () => {
      try {
        const msgStream = client.messages.stream({ model: 'claude-sonnet-4-6', ... });
        let finalText = '';
        msgStream.on('text', (text: string) => {
          finalText += text;
          controller.enqueue(encoder.encode(`data: ${JSON.stringify({ text })}\n\n`));
        });
        await msgStream.finalMessage();
        // DB persist here (inside try/catch — non-fatal)
        controller.enqueue(encoder.encode(`event: done\ndata: {}\n\n`));
        controller.close();
      } catch (err) {
        controller.enqueue(encoder.encode(`data: ${JSON.stringify({ error: String(err) })}\n\n`));
        controller.close();
      }
    })();
  },
});
return new Response(stream, {
  headers: {
    'Content-Type': 'text/event-stream; charset=utf-8',
    'Cache-Control': 'no-cache, no-transform',
    'Connection': 'keep-alive',
    'X-Accel-Buffering': 'no',
  },
});
```

### Pattern 3: Client-Side SSE Consumer

**What:** `fetch()` + `ReadableStream.getReader()` — NOT `EventSource`. EventSource silently ignores POST bodies.

**Example (from app/daily-prep/page.tsx — verified):**
```typescript
// Source: /Users/jmiloslavsky/Documents/Panda-Manager/app/daily-prep/page.tsx lines 254–319
const response = await fetch('/api/daily-prep/briefing', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ date: selectedDate }),
});
const reader = response.body!.getReader();
const decoder = new TextDecoder();
let accumulated = '';
let lineBuffer = '';
while (true) {
  const { done, value } = await reader.read();
  if (done) break;
  lineBuffer += decoder.decode(value, { stream: true });
  const lines = lineBuffer.split('\n');
  lineBuffer = lines.pop() ?? '';
  for (const line of lines) {
    if (line.startsWith('data: ')) {
      const parsed = JSON.parse(line.slice(6));
      if (parsed.text) accumulated += parsed.text;
    }
    if (line.startsWith('event: done')) {
      // navigate to briefing tab
      router.push('/daily-prep/briefing');
    }
  }
}
```

### Pattern 5: Heuristic Query — JS-side Date Filtering

**What:** Fetch candidates without date filter in SQL (avoid lexicographic comparison on TEXT fields), filter in TypeScript using `parseFlexibleDate`.

**Why:** `actions.due`, `risks.target_date`, `milestones.date`, `wbs_items.due_date` are all TEXT with values like `'TBD'`, `'2026-Q3'`, or ISO `'2026-05-14'`. SQL `<= '2026-05-14'` will include `'2026-Q3'` (lexicographic) and exclude `'TBD'` only by accident. The codebase (lib/queries.ts:419) uses `new Date(value)` + `isNaN()` check to guard against non-ISO strings.

**Example:**
```typescript
// lib/daily-briefing.ts — new helper (Claude's discretion)
export function parseFlexibleDate(value: string | null | undefined): Date | null {
  if (!value) return null;
  const d = new Date(value);
  return isNaN(d.getTime()) ? null : d;
}

// Usage in heuristic:
const candidateActions = await db
  .select()
  .from(actions)
  .where(inArray(actions.status, ['open', 'in_progress']));

const today = new Date(); today.setHours(0, 0, 0, 0);

const todayActions = candidateActions.filter((a) => {
  const d = parseFlexibleDate(a.due);
  return d !== null && d <= today;
});
```

### Pattern 6: Chain-to-Briefing in handleGenerate()

**What:** After all per-event SSE streams complete, POST to `/api/daily-prep/briefing` and navigate on `event: done`. Must not change the existing parallel fire-and-forget pattern for per-event generation.

**What changes in page.tsx:**
```typescript
// Current handleGenerate() fires parallel fetch calls via forEach (NOT await)
// Add a Promise.all wrapper to detect when all per-event streams finish:
async function handleGenerate() {
  const selectedCards = cards.filter((c) => c.selected);
  if (!selectedCards.length) return;

  const perEventPromises = selectedCards.map((card) => generateSingleCard(card));
  await Promise.all(perEventPromises);
  // After all briefs done — start briefing synthesis
  await generateBriefing(selectedDate);
}
```

The existing parallel fire-and-forget is a `selectedCards.forEach(async (card) => {...})` — this must be extracted to a named async function and wrapped in Promise.all. This is the only behavioral change to `page.tsx`.

### Anti-Patterns to Avoid

- **SQL date comparison on TEXT fields:** `WHERE due <= '2026-05-14'` on a TEXT column that contains 'TBD' — wrong results, silent bugs.
- **EventSource for POST SSE:** EventSource only supports GET. Use `fetch()` + `ReadableStream.getReader()` (established by [79-04]).
- **Persisting partial stream content:** Only INSERT after `finalMessage()` resolves (after `event: done`). Partial persist would corrupt briefing content.
- **Not exporting `force-dynamic` on briefing page:** Required for all DB-backed pages in Docker (`CLAUDE.md`). The briefing page fetches from DB on mount — it must export `export const dynamic = 'force-dynamic'`.
- **Adding `status` to `key_decisions`:** The table is APPEND-ONLY with a DB trigger that prevents UPDATE/DELETE (schema.ts:265–278). Do not attempt to filter by status. Filter by `date >= today-7` only.
- **Importing `inArray` without verifying import:** The codebase has had issues with missing drizzle-orm imports causing 500s (STATE.md [85-01]). Always verify the import list includes every Drizzle helper used.

## Common Pitfalls

### Pitfall 1: TEXT Date Heuristics Return Wrong Rows

**What goes wrong:** SQL `WHERE due <= '2026-05-14'` on TEXT column includes '2026-Q3' (lexicographically less than '2026-05-14' after the dash character position differs). 'TBD' would be excluded but '2026-Q3' would appear as if due last year.

**Why it happens:** PostgreSQL TEXT comparison is lexicographic, not date-aware.

**How to avoid:** Fetch candidates with only the status filter in SQL. Apply date range filtering in TypeScript after calling `parseFlexibleDate()`.

**Warning signs:** Action items showing up from quarters in the past or future in the briefing.

### Pitfall 2: layout.tsx Triggers SSR/Hydration Issues

**What goes wrong:** If `app/daily-prep/layout.tsx` is a Server Component (default when no `'use client'` directive), `usePathname()` will throw at build/runtime.

**Why it happens:** Next.js App Router: hooks only work in Client Components.

**How to avoid:** Always add `'use client'` at the top of `layout.tsx`. Verified pattern: `AppChrome.tsx` and `PageBar.tsx` both use `'use client'` + `usePathname()`.

**Warning signs:** Build error: `Error: useState can only be used in a Client Component`.

### Pitfall 3: Promise.all Wrapping Breaks Parallel Generation

**What goes wrong:** Refactoring `selectedCards.forEach(async...)` to `Promise.all` changes timing. If not done correctly, cards could generate sequentially or the parallel state updates could conflict.

**Why it happens:** `forEach` fires fire-and-forget async calls (existing pattern). Wrapping in `Promise.all` means the component waits before chaining. If `generateSingleCard` is not properly extracted, state updates inside the loop may close over stale state.

**How to avoid:** Extract the inner loop body to a standalone async function. Verify that `setCards` functional updater form (`setCards(prev => ...)`) is used everywhere inside the extracted function (it is, in the existing code).

**Warning signs:** Cards generating one at a time instead of in parallel.

### Pitfall 4: Briefing Streamed Before All Per-Event Briefs Complete

**What goes wrong:** The briefing synthesis fetches `daily_prep_briefs` for today but some per-event briefs haven't been persisted yet (their SSE streams are still in flight).

**Why it happens:** If briefing POST is sent before the `Promise.all` over per-event streams resolves.

**How to avoid:** Only call POST `/api/daily-prep/briefing` inside `.then()` or `await` after the `Promise.all`. The `event: done` sentinel in the per-event streams confirms DB persistence has occurred (the generate route persists before sending `event: done`).

**Warning signs:** Briefing's "Today's Meetings" section missing some meetings.

### Pitfall 5: Missing `isNull` / `inArray` Drizzle Imports

**What goes wrong:** Route returns HTTP 500 with a `TypeError` at runtime because a Drizzle helper is called but undefined.

**Why it happens:** Tree-shaking and named imports. The project has a documented history of this ([85-01]: `isNull()` from drizzle-orm required for nullable parent_id comparisons).

**How to avoid:** For the briefing route, the likely needed imports are: `eq`, `and`, `inArray`, `gte`, `lte`, `or`, `isNull` (from `drizzle-orm`). Import all that are used; verify the import list against actual usage.

**Warning signs:** 500 on `POST /api/daily-prep/briefing` in development.

### Pitfall 6: `key_decisions` Has No Status Field

**What goes wrong:** Planner attempts to add a `status` column to `key_decisions` or filter by status.

**Why it happens:** The original spec brainstormed "pending decisions"; this data model doesn't support it.

**How to avoid:** Filter only by `date >= today-7`. The `key_decisions` table is APPEND-ONLY with a DB trigger preventing UPDATE/DELETE (schema.ts lines 265–278, migration-enforced trigger). Do not add a `status` column.

### Pitfall 7: Freebusy Scope Banner Overlap

**What goes wrong:** If the layout.tsx renders `SubTabBar` above the existing `app/daily-prep/page.tsx` content, the sticky positioning of SubTabBar (`sticky top-[41px]`) may overlap with the scope banner.

**Why it happens:** The SubTabBar uses `sticky top-[41px]` (the PageBar height offset). The briefing page doesn't have this problem since it starts empty, but the Calendar tab's scope banner sits below the sub-tab bar.

**How to avoid:** No change needed — the SubTabBar `top-[41px]` offset is correct; it sticks below the 36px PageBar. The scope banner is inside the page content, below the SubTabBar.

### GET briefing endpoint (mirrors briefs/route.ts)
```typescript
// Source: pattern from app/api/daily-prep/briefs/route.ts
export async function GET(request: NextRequest): Promise<NextResponse> {
  const { session, redirectResponse } = await requireSession();
  if (redirectResponse) return redirectResponse as NextResponse;
  if (!session) return NextResponse.json({ error: 'Unauthorized' }, { status: 401 });

  const date = new URL(request.url).searchParams.get('date');
  if (!date) return NextResponse.json(null);

  const [row] = await db
    .select()
    .from(dailyBriefings)
    .where(and(eq(dailyBriefings.user_id, session.user.id), eq(dailyBriefings.date, date)))
    .limit(1);

  return NextResponse.json(row ?? null);
}
```

## Open Questions

1. **Empty data day handling — should synthesis be skipped?**
   - What we know: If no calendar events + zero open actions + zero critical items, calling Claude produces a vapid result ("There's nothing scheduled today.").
   - What's unclear: Whether a no-op is better UX than an empty-message briefing.
