# Phase 85.1: Screen Density & UX Overhaul — Context

**Gathered:** 2026-05-11
**Status:** Ready for planning

<domain>
## Phase Boundary

Hard-set a denser default across the entire app — visual-only changes; no data, API, or behavioral changes. Three layers, all in scope:

1. **Global chrome** — Sidebar (Command Rail), PageBar, WorkspaceTabs row, SubTabBar, page-wrapper padding.
2. **Shared primitives** — `components/ui/*` (Table, Input, Select, Button, Dialog, Textarea, etc.) tightened at the source so every consumer inherits density.
3. **Per-tab cleanup** — Sweep all ~28 workspace tabs and global pages to remove residual loose spacing (hardcoded `p-6`, `space-y-6`, custom card paddings) that survives the primitive pass.

Reference target: **Linear-style** density. Promoted ahead of Phase 86 (AWS readiness) because screen-real-estate pain is hurting daily use.

</domain>

<decisions>
## Implementation Decisions

### Density Target (anchors everything else)

- **Reference app:** Linear-style — dense enough to fit a lot on screen, still comfortable for daily 8-hour use.
- **Body text:** 13px (`text-[13px]`), metadata 12px (`text-xs`). Headings stay at current KDS sizes (JBM 64px hero, 28px KPI).
- **Row heights:** Body rows 32px (`h-8`), headers 36px (`h-9`). Cells `py-1.5 px-3`.
- **Section padding:** `p-4` sections (was `p-6`), `gap-3` stacks (was `gap-4`/`gap-6`).
- **Line-heights:** `leading-5` on body (was `leading-6`), `leading-tight` on headings.

### Token Architecture (extends KDS Phase 81)

- **Extend `kata-tokens.css`** with a spacing scale and semantic height tokens. Keep the existing two-layer (palette + semantic) pattern.
- **Spacing scale — 4px base, 8-step:**
  - `--kata-space-1` = 4px
  - `--kata-space-2` = 8px
  - `--kata-space-3` = 12px
  - `--kata-space-4` = 16px
  - `--kata-space-5` = 20px
  - `--kata-space-6` = 24px
  - `--kata-space-7` = 32px
  - `--kata-space-8` = 48px
- **Semantic height tokens:**
  - `--kata-row-sm` = 28px
  - `--kata-row-md` = 32px
  - `--kata-row-lg` = 36px
  - `--kata-input` = 32px
  - `--kata-input-lg` = 36px
- **Tailwind connection:** Override the Tailwind `spacing` scale in `tailwind.config` / `@theme inline` so default classes (`p-3`, `gap-3`, `h-8`, etc.) resolve to `var(--kata-space-*)`. One config change cascades app-wide; existing utility classes silently use the new tokens. Reversal is one file.
- **No new prefix:** Reusing default Tailwind class names (`p-3` not `p-kata-3`) keeps the codebase familiar and avoids touching every file just to be "on the system."

### Global Chrome Trim

- **Sidebar (Command Rail) — 240px width preserved (KDS-03 locked):**
  - Header: `py-3.5` → `py-2` (32px row).
  - Top nav rows (Portfolio, Daily Prep): `py-1.5` → `py-1` (28px row).
  - Project list rows: 28px height.
  - Search pill: `h-7` → `h-6` (24px).
  - Section gaps: `space-y-0.5` → `space-y-0` (rely on row height for separation).
  - Additional nav (Weekly Report, KB, Outputs, Settings, Scheduler, Time Tracking) bottom strip: same `py-1` row spec.
- **PageBar — 44px → 36px (`h-9`).** Title stays `text-sm`. Theme toggle button: 28×28 → kept (already correct for new bar height). KDS-04 spec said 44px; CONTEXT.md amends this to 36px to fit the denser direction.
- **Tab rows — keep two-row structure (top-level + sub-tab), trim each:**
  - Top `WorkspaceTabs`: `px-4 py-2` → `px-4 py-1.5`, `text-sm`.
  - `SubTabBar`: `py-1.5` → `py-1`, `text-sm`.
- **Page wrappers — `p-6` → `p-4` uniform** across all `/customer/[id]/{tab}/page.tsx` and global pages (`/`, `/daily-prep`, `/weekly-report`, `/knowledge-base`, `/outputs`, `/scheduler`, `/time-tracking`, `/settings`, `/search`).

### Shared Primitives (`components/ui/*`)

- **`ui/table.tsx` — override base styles globally:**
  - `TableHead`: `h-12 px-4` → `h-9 px-3 py-1.5`.
  - `TableCell`: `p-4` → `px-3 py-1.5` (yields 32px body row).
  - Every consumer (Actions, Risks, Milestones, Decisions, Stakeholders, Members tables) becomes denser automatically. Zero per-file edits required to pick up the new density.
- **`ui/input.tsx`, `ui/select.tsx`, `ui/button.tsx`:**
  - Default `h-10` → `h-8` (32px) on all three.
  - Button `sm` variant `h-9` → `h-7` (28px). `lg` stays at `h-10`.
  - Padding and text size scale proportionally (`text-sm` everywhere by default).
- **`ui/dialog.tsx`:**
  - `DialogContent`: `p-6` → `p-4`.
  - `DialogHeader`: `p-6 pb-4` → `p-4 pb-2`.
  - `DialogFooter`: `p-6 pt-4` → `p-4 pt-2`.
  - `DialogTitle`/`DialogDescription` spacing reduced to match.
- **`ui/card.tsx`:** `CardHeader` / `CardContent` / `CardFooter` default `p-6` → `p-4`; `gap-1.5` between header items kept.
- **`ui/textarea.tsx`:** Default `min-h-[80px]` → `min-h-[64px]`, `px-3 py-2` → `px-3 py-1.5`.

### Per-Tab Sweep

- **Scope:** All ~28 workspace tabs (Overview, Plan, Gantt, WBS, Tasks, Actions, Risks, Milestones, Decisions, Teams, Architecture, Stakeholders, Skills, Chat, Context, Time, Artifacts, Queue, History, Members, Settings) + global pages (Portfolio Dashboard, Daily Prep, Weekly Report, Knowledge Base, Outputs, Scheduler, Time Tracking, Search).
- **Sweep targets:** Hardcoded `p-6` / `space-y-6` / `gap-6` in page bodies, custom card paddings, oversized section headers, redundant wrapper divs that nest paddings, KPI strips with loose internal spacing.
- **Inherited automatically** (no per-file work needed once primitives are tight): every table consumer, every dialog/modal, every Input/Select/Button.
- **Exclusions — leave as-is, do NOT re-tighten:**
  - **WBS grid** — just shipped in Phase 85 (MS Project style). Already spec-tight. Sweep verifies chrome integration only; does not touch grid internals (`WbsGrid.tsx`, `WbsPageClient.tsx`).
  - **Gantt** — carefully tuned bar heights, row geometry, milestone markers, baseline ghost bars. Density already correct. Sweep verifies the surrounding page wrapper only; does not touch `GanttChart.tsx` internals.
- **Included in sweep (will get density pass):** Chat panel, Skills output, Knowledge Base entries, Outputs Library previews, Context Hub artifact previews, Task Board kanban columns. Content surfaces get the same density treatment as everything else — reduce padding/gaps, tighten typography, but no behavioral changes.

### Claude's Discretion

- Exact `--kata-space-*` token CSS comments and ordering in `kata-tokens.css`.
- Where token references live in `tailwind.config.ts` (theme.extend vs theme override).
- Specific Badge / Chip / Tooltip / Toast sizes — apply consistent 28px chip height, 24px badge, but pixel-perfect details are flexible.
- Focus ring width and offset on tighter inputs.
- Hover/active state padding nudges if visually needed.
- Per-tab edge cases where a section legitimately needs `p-4` instead of `p-3` for visual rhythm.
- Whether to introduce `--kata-radius-*` tokens alongside spacing (out of scope unless trivial).

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `components/kata-tokens.css` (~125 lines, colors only today) — extend with spacing + height tokens following the existing two-layer pattern. No new file needed.
- `components/Sidebar.tsx` (165 lines) — direct paddings/heights to update (`px-4 py-3.5`, `px-3 py-2.5`, `h-7`, `py-1.5` in nav). KDS data-theme="dark" pattern stays intact.
- `components/PageBar.tsx` (93 lines) — inline `height: 44` style literal → 36; theme toggle button geometry already correct.
- `components/WorkspaceTabs.tsx` (152 lines) — `px-4 py-2` on Link className strings; both active and inactive variants need the same trim.
- `components/SubTabBar.tsx` — sibling trim alongside WorkspaceTabs.
- `components/ui/table.tsx` (118 lines) — single file holds TableHead `h-12 px-4` and TableCell `p-4`. One override touches the entire app's table layer.
- `components/ui/input.tsx`, `ui/select.tsx`, `ui/button.tsx`, `ui/dialog.tsx`, `ui/card.tsx`, `ui/textarea.tsx` — shadcn defaults; height/padding live in `cva` variants or className strings.
- `components/AppChrome.tsx` (28 lines) — NO_CHROME_PATHS suppression preserved; not affected.

### Established Patterns
- **Two-layer Kata token architecture** (palette + semantic) — spacing additions follow this exact shape: define raw scale at palette level, name semantic intents (`--kata-row-md`) at the second layer.
- **CSS variables consumed via inline style or Tailwind alias** — both patterns already in use (Sidebar uses `style={{ background: 'var(--kata-gray-950)' }}`; tables use Tailwind utilities). New spacing tokens fit both consumption modes.
- **`data-theme="dark"` isolation** on Command Rail — density tightening must not break dark-isolation (`<aside data-theme="dark">` keeps its tokens regardless of `<html class="dark">`).
- **`requireSession()` + `requireProjectRole()` security boundary** — not touched by this phase.
- **shadcn `cva` variant pattern** — Button uses `cva` for size variants. Adding/modifying `size: { sm, default, lg }` is the standard knob.
- **`@theme inline` in `app/globals.css`** — already where shadcn tokens alias to Kata. Tailwind spacing override goes here (or in `tailwind.config.ts` if present).

### Integration Points
- `components/kata-tokens.css` — primary source of new tokens.
- `app/globals.css` / `tailwind.config.ts` — Tailwind spacing scale override (the single config change that cascades to every existing utility class).
- `components/ui/*` — primitive overrides; each is a small, isolated file edit.
- `components/Sidebar.tsx`, `PageBar.tsx`, `WorkspaceTabs.tsx`, `SubTabBar.tsx` — chrome surfaces, manual edits.
- `app/customer/[id]/{tab}/page.tsx` (×~20 routes) + global pages — page-wrapper `p-6` → `p-4` sweep; expect mostly find-and-replace across page-level wrappers.

### Risks / Things to Watch
- **Tailwind spacing override is the riskiest single change** — if `p-3` value flips unexpectedly, every existing utility usage shifts. Recommend keeping the override values identical to Tailwind defaults (i.e., `p-3` stays 12px) so the override is a transparent indirection, NOT a redefinition. Density comes from the codebase sweep using denser values (`p-6` → `p-4`), not from changing what `p-4` means.
- **KDS visual rhythm** — Portfolio hero band (JBM 64px) and KPI strip (JBM 28px) need to still feel intentional next to denser surrounding chrome. If 36px PageBar + 32px sidebar rows + 64px hero numerals starts to look visually unbalanced, KPI strip may need a tiny padding adjustment (Claude's discretion).
- **Dialog/Modal forms with many fields** — Phase 78 Add Action, Add Milestone modals are already moderately tight. Confirm `h-8` inputs still hit accessibility targets (min 24×24 click area).

</code_context>

<specifics>
## Specific Notes

- **Linear is the explicit visual reference.** When in doubt during planning/implementation, look at Linear's table density, row heights, and chrome footprint.
- **KDS-03 240px Sidebar width is honored**, not amended. Width stays; only internal rows tighten.
- **KDS-04 44px PageBar is amended to 36px** — this is the single KDS-spec change Phase 85.1 makes. Worth calling out in the planner's task list so verification covers it.
- **Density override is transparent.** `p-3` still means 12px; the sweep changes `p-6 → p-4` everywhere, not the meaning of `p-4`. This keeps Tailwind docs and IDE autocompletion accurate and makes the change reversible by reverting the sweep.
- **No user-facing density toggle.** "Hard-set denser default" — this is the new baseline, not a setting. The "Mixed by surface type" option was explicitly NOT picked.
- **Sweep order suggestion** (planner discretion): tokens first → primitives second → chrome third → per-tab sweep fourth. Each layer's density cascades down so per-tab work is residual cleanup, not redundant pixel-pushing.

</specifics>
